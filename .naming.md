# Naming Skill

Adapted for this repository from the metaphor-driven `glacierphonk/naming`
method. Use this whenever naming or renaming the product, modules, editions,
or public-facing features.

## Core stance

Do not brainstorm randomly. Do not start with names.

The goal is not a name that describes the app. The goal is a name people
remember, trust, and would believe is a real product used on race day.

Prefer names with:

- a concrete metaphor or origin story
- strong spoken form in Czech and English
- clean ASCII domain/app/package form
- logo potential
- authority under pressure
- a 10-20 year shelf life

Reject names that merely sound like generic SaaS.

## Product context

This product is an offline Electron desktop app for motorsport timing and race
administration. It replaces Excel-based timing workflows for rallycross,
autocross, hill climb, hobby, and semi-professional events.

The name must fit:

- race organizers
- timekeepers
- sport commissioners
- category/final/heat workflows
- measured times, grids, results, penalties, and PDF exports
- local-first Windows/macOS desktop use
- Czech domestic use and possible international use

The product is not only a stopwatch. It is a timing, results, and race-control
instrument that becomes an authority for what happened.

## Process

### 1. Build the naming brief

Before generating names, establish:

1. What does the product do in one sentence?
2. Who uses it on race day?
3. What must the name feel like?
4. Is the name standalone, or part of a product family?
5. Which words, tones, or naming patterns are forbidden?
6. Which surfaces must the name work on?
   - app title
   - installer name
   - domain
   - GitHub/package names if relevant
   - PDF/export headers if relevant

### 2. Map metaphor territories

Do not search for synonyms of time, speed, race, or timer.

Ask:

1. What does this job in the physical world?
2. What does this job in motorsport?
3. What tool or machine is analogous?
4. What role or profession is analogous?
5. What is the dramatic version of the job?
6. What is the quiet version of the job?

Useful territories for this repository:

- measurement line: beam, gate, stripe, mark, loop, split, sector
- race authority: marshal, steward, clerk, ledger, register, verdict, order
- race structure: grid, heat, stage, final, lane, draw, bracket
- precision instruments: caliper, chronometer, scale, datum, gauge, vernier
- signal systems: beacon, pulse, flag, lamp, timing light, transponder
- memory/audit: logbook, ledger, trace, archive, record
- terrain and rallycross: gravel, tarmac, joker, paddock, parc, crest
- navigation/reference: line, bearing, meridian, waypoint, datum

Cross-pollinate territories when useful:

- timing line x official record
- race grid x measurement instrument
- signal x authority
- terrain x precision
- audit trail x race result

### 3. Generate internally

Generate a large raw list, including weak candidates, but do not present the raw
list unless the user explicitly requests it. Use:

- real words
- concrete compounds
- modified real words
- short coined words rooted in recognizable morphemes
- Czech/English hybrid candidates only when they survive pronunciation tests

### 4. Kill weak names

Immediately reject:

- category labels: RaceTime, SpeedTimer, LapTimer, RaceTrack Pro
- fake authority: TimeMaster, ChronoMaster
- AI/startup slop: Syncora, Nexagen, Brightrix, Flowly, TaskHub, AppBase
- empty suffixes: -ly, -ify, -able, -ora, -ix, -io when decorative
- vague corporate words: Solutions, Labs, Platform, HQ, Systems, Technologies
- generic compounds: DataSync, SmartHub, AutoFlow, CloudBase
- excessive misspelling or missing vowels
- names that fail the phone test
- names with no 15-second origin story

If a compound has two halves, both halves must earn their place. Cover either
half. If the remaining half carries no useful image, the compound is weak.

### 5. Language filter

Check:

- Czech pronunciation
- English pronunciation
- ASCII spelling
- diacritics strategy
- visual form in title case and lowercase
- whether the name sounds serious when spoken by a race director
- whether a timekeeper can say it calmly over a noisy event

For Czech names, prefer an ASCII primary form for domains and app internals.
Use diacritics as local display only when valuable.

### 6. Availability filter

For finalists, do real checks before recommending:

1. Search for direct competitors in timing, motorsport, race management,
   rallycross, or sports timing.
2. Search for broad software/app conflicts.
3. Check likely domains or domain strategies:
   - exact `.com` where realistic
   - `.app`, `.co`, `.dev`, or audience suffixes
   - `get[name].com`, `use[name].com`, `[name]timing.com`
4. Treat strong names with workable domain strategies as viable, but flag risk.

Do not claim legal availability. Trademark clearance requires a separate check.

### 7. Score finalists

Score on:

- memorability
- distinctiveness
- pronunciation
- semantic fit
- metaphor strength
- motorsport fit
- software fit
- logo potential
- international usability
- long-term brand potential

Use strict judgment. It is acceptable to conclude that the current name is
still stronger than the alternatives.

### 8. Present decision-quality output

Final output should include:

- naming brief
- metaphor territories explored
- rejected patterns
- shortlist with origin stories
- risks and trade-offs
- TOP 20 / TOP 10 / TOP 5 when requested
- one recommended winner
- a note comparing the winner against `Casomira` / `Casomira Timing`

Never present a name without a reason. Never present a name only because it
sounds modern.
